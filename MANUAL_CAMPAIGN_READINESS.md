# Manual campaign launch

Creating a campaign saves a draft, regardless of a supplied create status. Save draft never queues recipients or calls a message provider. Launch is a separate authenticated action. A paused dispatcher, inactive company or blocked channel now returns a visible error before any recipient is queued; the builder no longer reports a failed launch as successful. New drafts default to the requested 09:00–20:00 America/New_York window.

When an eligible Smartlead email campaign is explicitly launched, the server prepares a separate, empty provider campaign using only verified mailboxes belonging to that business. It preserves the mailbox daily limit, applies the campaign's sending window, configures reply/bounce/unsubscribe callbacks and saves the campaign's own copy. Setup does not upload leads or request START. Only the worker processing the explicitly queued campaign submits recipients and starts its independent provider campaign. Existing campaigns' copy and recipients are not reused or overwritten.

The EmailCampaignSetup table stores the original business, message/schedule fingerprint, provider ID and setup state. Concurrent launches reserve one setup; ambiguous provider creation requires reconciliation rather than blindly creating another campaign. Configuration failures after the provider ID is saved can reuse that same empty provider campaign. Callbacks resolve these durable mappings to the correct CRM campaign and inbox. Existing provider mappings remain supported for legacy callbacks and already queued snapshots.

Manual-only production readiness requires old sending/scheduled campaigns paused, autopilot disabled and no queued/processing recipients before SENDING_ENABLED is enabled. ACTIVE_SENDING_ENTITIES=abstract and SENDING_CHANNELS=email restrict the initial rollout. Inbox responses remain separately controlled. SMS registration is still pending, and other companies require verified sender configuration. Idle workers stop rescheduling when no eligible scheduled/queued work remains.

Migration 202610200004_manual_campaign_setup is additive. It was tested against the isolated preview schema and temporary PostgreSQL-compatible test database. Automated checks cover saving without arming a campaign, paused/channel guards, independent provider copy and schedules, mailbox ownership, uncertain creation, concurrent preparation, new-campaign callback routing, one queued recipient after a deliberate launch, and repeated-launch deduplication. All provider calls in these tests are mocked. No production campaign is launched as part of this repair.
